# WP-02 explained: icons

## What was built

Every item in every collection now has a small picture beside its name: 28 pixels in the table, 64 pixels at the top of the Details window. All 1,052 items that have a game picture show that picture. The 26 entries that aren't items (16 ways to die and 10 kinds of tree) each get their own little engraved drawing instead.

All the pictures ship inside the app. It never downloads anything while you use it, so it still works offline and still sends nothing anywhere.

### Where the pictures come from

A script, `tools/harvest-icons.mjs`, goes looking for each item's picture. It tries these places in order and stops at the first one that has it:

1. **The Jötunn documentation** (A). Jötunn is an open-source toolkit for Valheim modders. Its documentation includes a 128 × 128 picture of nearly every item, building piece and creature, and it uses the MIT licence, which allows reuse. Git (a tool for copying code projects) isn't installed on your Mac, so the script downloads the project as one compressed file instead and unpacks only the documentation folders. That's about 37 MB, kept in a temporary folder outside the project.
   - Items and pieces are matched by their **token**, the game's internal name such as `$item_club`.
   - Creatures use their **trophy** picture when there is one, because the other creature pictures are stiff "T-pose" renders (arms straight out, like a mannequin).
   - Then `src/icons/overrides.json` fixes the few items the automatic match gets wrong. Every override picture was looked at by eye before it was accepted, and each entry says what it shows.
2. **valheim.tools** (B). This site refused the script (HTTP 403, "forbidden"), as the spec expected. The script notes that and moves on.
3. **The Valheim wiki** (C). This worked for 4 items: Dundr, Troll, Lingonberries and Grilled Neck Tail.
4. **Hotlink** (D). If the wiki had a picture but downloading it failed, the app would load it from the wiki at runtime (while you use it). That wasn't needed, so there are none.
5. **Glyph** (E). A simple line drawing for each kind of thing (weapon, armour, tool, food, building piece, creature, trophy, fish). Every one of the 26 death and tree entries has its own glyph.

### Two surprises, and what I did about them

- **Some Jötunn pictures are empty.** Ten of them are fully see-through, or hold only a few scattered sparkles: all seven "Aspect of …" creatures, plus Troll, Lingonberries and Grilled Neck Tail. The script now measures how much of each picture is actually visible. Anything under 1.5% counts as blank and goes on to the next source. (The thinnest real icons, arrows and spears, are about 2%.)
- **The Aspects aren't on the wiki either.** The Aspects are ghostly copies of earlier bosses, summoned in the final boss fight. Each one now shows its boss's trophy tinted pale ghost-blue, so "Aspect of the Living Forest" shows The Elder in blue. The tint keeps it from looking like the trophy row. This one is a judgement call, flagged for the orchestrator.

### Packing the pictures into one image

Loading 1,052 separate little files would be slow, so the script pastes them all onto one big sheet called an **atlas** (`src/icons/atlas.webp`). The sheet is a grid of 32 × 31 squares, each 96 pixels across. Identical pictures share one square, which leaves 991 squares. WebP is a compact image format, and the whole sheet is 1.39 MB, well under the 4 MB limit. To show one icon, the page shows the sheet behind a small window and slides it until the right square lines up. That's a CSS trick called a *sprite*.

`src/icons/icon-map.json` is the index: for every token it says which square to use, or which glyph. `src/icons/coverage.md` is a readable report of where every picture came from.

### Making them look printed

The icons get a 15% sepia tone (a warm brown tint, like old photos) and a faint grainy mask, so they look printed onto paper rather than pasted on. The spec also asks for a *multiply* blend, which lets the paper show through the ink. On the current dark page that would turn the icons black, so it switches on only where the page is paper: the 3D desk (WP-04 onward) and the parchment page (WP-13).

### A privacy detail

The one-file build stores the atlas as a long string of letters and digits. By pure chance, five of those letters spelled your character's name in a different letter case. It was not your name, just noise, but a privacy check would rightly flag it. When `fixtures/private/` exists, the script now checks for that and re-packs the image slightly differently if needed. It reads the private file but never prints or writes what's in it.

## Which files

| File | What it is |
| --- | --- |
| `tools/harvest-icons.mjs` | Finds every picture (A → E), packs the atlas, writes the files below. Run it with `npm run icons` |
| `src/icons/overrides.json` | Hand-checked fixes, each with a note of what the picture shows |
| `src/icons/atlas.webp` | All bundled pictures on one sheet |
| `src/icons/icon-map.json` | Token → square, hotlink or glyph |
| `src/icons/sources.json` | Where each picture came from; the script reads it back next time |
| `src/icons/coverage.md` | Counts per source and the list of everything not matched automatically |
| `src/icons/glyphs.js` | The 34 engraved line drawings |
| `src/icons/lookup.js` | Picks the right icon for an item (no browser needed, so it can be tested) |
| `src/icons/icons.js`, `icons.css` | Put icons into the page: table rows, Details, the footer credit |
| `src/strings.js` | New text: the credit line and the (currently unused) hotlink privacy sentence |
| `src/config/render.js` | New `icons` settings: 28 px, 64 px, 15% sepia, grain strength |
| `unit/icons.test.mjs` | 15 tests for all of the above |

`src/app.js` didn't change. The icon code watches the table, and every time the app redraws it, the code adds the pictures again.

## How it works, in one paragraph

When the page starts, `icons.js` reads the same catalog the app reads and learns which tokens belong to each row. Every row in the table carries its item's id (`data-item`), so after each redraw the code finds the row's tokens, asks `icon-map.json` which square to show, and puts a small `<span>` in front of the item name. The span shows that square of the atlas. When Details opens, the app announces `app:details-open` on the event bus (the noticeboard from WP-01), and the code puts a bigger icon beside the title. Each icon is marked `aria-hidden` (screen readers skip it), because the item's name sits right next to it.

## One thing to try

Open the browser console on the app (right-click → Inspect → Console) and type:

```js
__vc.icons.stats()
```

You'll see `{tokens: 1078, cell: 1052, hotlink: 0, glyph: 26, hosts: []}`. That's every token, how many have a bundled picture, and how many use a glyph. Then open `src/config/render.js`, change `rowPx: 28` to `rowPx: 48`, run `npm run build:single`, and reload the app: the table icons get bigger.
