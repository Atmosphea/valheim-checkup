# WP-01 explained: project setup and event bus

## What was built

The app looks exactly the same as before, and that was the goal. What changed is underneath: the app now runs through a modern build tool, and the building blocks every later step needs are in place.

1. **A build tool (Vite).** A build tool takes many source files and packs them into something a browser can open. You get three commands:
   - `npm run dev` starts a small local web server (a program that serves the page to your browser at `http://localhost:5173/`). It reloads the page whenever you save a file.
   - `npm run build:single` makes `dist/valheim-checkup.html`, **one file with everything inside it**. Double-click it and it opens in your browser, even offline.
   - `npm run build:site` makes `dist/site/`, the same app as separate files, for putting on a website later.
   - The old `npm run build` still works and makes `dist/original.html`, the original page.
2. **The original parser stays untouched.** `src/core.js` (the code that reads your `.fch` save) and `src/catalog.json` (the list of every achievement item) are copied into the page byte for byte by a tiny plugin, `tools/vite-plugin-inline-legacy.mjs`. A plugin is a small add-on that teaches Vite one extra trick.
3. **An event bus** (`src/bus.js`). Think of it as a noticeboard. When something happens, say a save loads, the app pins a note on the board: `emit('app:load', {ok: true})`. Any other part of the program can watch for that note with `on('app:load', …)`. Later, the sound engine will listen for `app:load` and play a bell, and the coins will listen and flash gold. The app doesn't need to know any of that exists.
4. **A debug window** (`window.__vc`). It's a set of tools the tests (and you) can use from the browser console. It shows the last 2,000 notes from the noticeboard, the current state of the app, and controls for slow motion, randomness and quality.
5. **Shared helpers** in `src/util/`, each with tests in `unit/`:
   - `clock.js`: one clock for every animation. Slowing it down slows down everything at once.
   - `rng.js`: one "random" number generator that can repeat itself. Give it the same *seed* (starting number) and it produces the same "random" numbers again, so a test can replay exactly what happened.
   - `spring.js`: a spring, the maths behind things that bounce and settle naturally. You set how stiff it is and how much it's damped (slowed down, like moving through oil), and it moves toward its target.
   - `ease.js`: easing curves. These make motion start or stop gently instead of at a constant robotic speed.
6. **Settings files** in `src/config/`: `motion.js` (how things move), `render.js` (how things look) and `audio-mix.json` (all 69 sounds). Every number from the spec lives here, so tuning means editing one file.
7. **A mode switch** (`src/mode.js`). It decides whether a browser gets the 3D desk or the flat page. The 3D desk doesn't exist yet, so for now the answer is always "flat".

## How it works

When the page opens, the browser first runs the two original scripts inside the page (the catalog and the parser). Then it runs `src/main.js`. That loads `debug.js`, which sets up the clock, the random numbers, the mode and `window.__vc`, and then loads the original `app.js`. Because the debug window exists before the app starts, every note the app pins on the noticeboard gets recorded.

**Privacy.** Some notes would contain your character's name, for example the toast "Loaded *name*. Progress is up to date." Before the noticeboard stores a note, it swaps the name for `{name}`. The name still appears on screen, but never in `__vc.events`, so test logs and reports can't leak it. It does the same, in any mix of capital and small letters, for the save's profile id (a long number that identifies the character) and its fingerprint (a code computed from the save file). `src/privacy.js` tells the noticeboard what to hide: the name shown in the header, and the id and fingerprint the app keeps in browser storage.

One small trick: `app.js` now begins with `import { emit } from './bus.js';`. "Import" means "borrow this function from that file". The old build script can't follow imports, so when it builds `dist/original.html` it swaps that line for an `emit` that does nothing. The original page works exactly as before.

## One thing to try

1. Run `npm run build:single`, then double-click `dist/valheim-checkup.html`.
2. Open the browser's developer console (Chrome: View → Developer → JavaScript Console).
3. Type `__vc.state()` and press Enter. You'll see which collection is open, the record mode and the filters.
4. Click a different collection on the left (try Artisan), then type `__vc.events.slice(-2)`. Those are the last two notes on the noticeboard: `app:render` (the page was redrawn), then `app:category` with the collection's name. Pick Carpenter instead and a third note, `app:toast`, follows, because Carpenter shows the Unverified message.
5. Type `__vc.seed(5); __vc.rng.next()` and press Enter, then run that same line again. The same number comes out both times, which is the "repeatable random" idea.
